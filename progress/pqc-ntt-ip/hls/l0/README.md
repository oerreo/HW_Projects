# L0 Catapult HLS 빌드 (`mod_red`, `mod_mul`)

hand RTL(`rtl/l0/`)과 같은 블록을 Catapult HLS로 생성하고, hand RTL과 같은 TB(`tb/l0/tb_mod_red.sv`, `tb_mod_mul.sv`, 수정 없음)와 같은 exhaustive 벡터로 검증하는 흐름이다.
Catapult 수치는 모두 Catapult 내부 라이브러리 기반 추정치이며 합성 결과가 아니다.

## 디렉토리
| 경로 | 내용 | 커밋 |
|---|---|---|
| `include/mlkem_red_hls.h` | `ac_int` 기반 reduction 4종과 `mod_mul` 4종. golden `model/include/mlkem_modarith.h` 와 같은 단계, 같은 선언 폭 | O |
| `src/<block>.cpp` | Catapult top 함수 8개 (`mod_red_<algo>`, `mod_mul_<algo>`). 이름은 `HLS_TOP` 매크로 | O |
| `test/` | C 수준 exhaustive 테스트 (`make test`) | O |
| `tcl/hls_l0.tcl` | 공용 Catapult 흐름 (환경변수로 block, lib, cfg, clock) | O |
| `tcl/run_cfg.sh` | 한 구성 실행 (`run/<top>/`) | O |
| `tcl/run_all.sh` | 전 구성 순차 실행 + `out/` 수집 | O |
| `wrap/mod_red.sv`, `wrap/mod_mul.sv` | hand RTL과 같은 모듈 이름/파라미터/포트의 어댑터 | O |
| `wrap/hls_l0_lib_{fpga,asic}.sv` | 어댑터가 쓸 라이브러리 빌드 선택 package | O |
| `out/<block>_<lib>_<cfg>/` | 생성 netlist `concat_rtl.v`, `rtl.rpt`, `cycle.rpt` | O |
| `report/hls_l0_report.py` | `summary.csv`, `summary.md` 생성 | O |
| `run/` | Catapult 프로젝트, 로그, C 테스트 바이너리 | X (`.gitignore`) |

## 실행 순서
```
source /home/theo/work/research/scripts/env.sh hls
make -C hls/l0/test test                      # C 수준: 8 함수 x 정의역 전체, OVERALL: PASS
./hls/l0/tcl/run_all.sh                       # 48 구성 순차 (블록 8 x lib 2 x cfg 3), 약 15분
export BLK_RE='^mod_red_k2red$' LIB_RE=asic CFG_RE=p1; ./hls/l0/tcl/run_all.sh   # 일부만 (환경변수 정규식)
./sim/run.sh hls_l0_mod_red_barrett_asic      # RTL sim (cfg 16개: hls_l0_<block>_<lib>)
python3 hls/l0/report/hls_l0_report.py        # report/summary.{csv,md}
```
선택과 구성은 인자가 아니라 환경변수로 넘긴다(`.claude/rules/process-privacy.md`). `run_cfg.sh` 는 실행 디렉토리(`run/<top>/`)에 `run.tcl` 을 만들어 `catapult -shell -f run.tcl` 로 실행하므로 명령행에 블록 이름이나 경로가 나오지 않는다. `run_cfg.sh` 는 flock으로 Catapult를 하나씩만 돌리고, 이 사용자의 무거운 툴 프로세스(catapult, vsimk, vlog, dc_shell 등)가 2개 이상이면 빈 슬롯을 기다린다.

## 구성
| cfg | Catapult 설정 | latency | 생성 포트 |
|---|---|---|---|
| c0 | top을 combinational CCORE (`solution design set <top> -top -ccore -combinational`, `CCORE_FLOW bottomup`) | 0 | `x`, `r` (mod_mul: `a`, `b`, `p`), 클럭 없음 |
| p1 | sequential CCORE, II = 1, `MAX_LATENCY 1`, 출력 write를 c-step 1에 고정 | 1 | `clk`, `rst_n`, `ccs_ccore_en`, (`ccs_ccore_start_rsc_dat`), `x_rsc_dat`, `r_rsc_z` |
| p2 | 같은 방식, c-step 2 | 2 | 같음 |

- 라이브러리: `fpga` = `mgc_Xilinx-ZYNQ-1_beh` (part xc7z020clg400-1), `asic` = `nangate-45nm_beh`.
- 클럭: fpga 40 ns, asic 6 ns (lib마다 하나, 모든 블록/구성 공통). 가장 느린 `mod_mul_shiftadd` 가 p1(latency 1)로 스케줄되는 가장 작은 값 근처의 정수다(fpga 35 ns, asic 5 ns에서는 SCHD-20 실패). `CLK_FPGA`, `CLK_ASIC` 환경변수로 바꿀 수 있다.
- 공통 directive: `OPT_CONST_MULTS full` (상수곱을 shift-add로. `use_library` 이면 Zynq 라이브러리가 SHIFTADD fold까지 DSP 곱셈기로 묶는다), `RESET_CLEARS_ALL_REGS no` (hand RTL처럼 데이터 레지스터 reset 없음), `ADVANCED_DPOPT false`, 비동기 active-low reset `rst_n`.
- 이름 충돌 방지: top 이름 = `<block>_<lib>_<cfg>` (`-DHLS_TOP`), `Output/SubBlockNamePrefix`, `PackageOutput` + `PrefixStaticFiles` 로 하위 모듈과 `ccs_in_v1` 같은 정적 모듈까지 구성마다 고유 이름이 된다. 그래서 한 블록의 여러 구성과 두 라이브러리를 한 work 라이브러리에 같이 컴파일할 수 있다.
- downstream 합성(Vivado, DC, RTL Compiler, Oasys)은 실행하지 않는다. `-rtlsyntool` 지정으로 생성되는 스크립트(`vivado_*`, `*.dc`)는 실행하지 않은 채 `run/` 에만 남는다.

## 어댑터가 추가하는 것 (`wrap/`)
- 포트 이름 배선(`.*`), `ccs_ccore_en = 1`, `ccs_ccore_start_rsc_dat = valid_i` (Catapult가 이 포트를 남긴 경우 1단 데이터 레지스터 enable로 쓰인다).
- `valid_o`: `valid_i` 를 LATENCY 단 지연한 플롭 (`rst_n` 으로 reset). hand RTL도 같은 수의 valid 플롭을 가진다.
- 시뮬레이션 전용 입력 범위 assertion (`L0_RANGE`), hand RTL과 같은 정의역.
- QoR 비교 시 생성 모듈이 HLS 데이터패스이고, valid 플롭 LATENCY 개는 어댑터 소속이다.
- `mod_mul` 은 HLS 빌드에 절단 위치 구분이 없으므로 `LATENCY = MUL_REG + RED_PIPE` 로 빌드를 고른다. LATENCY 3 빌드는 없다.
