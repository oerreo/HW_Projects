# Catapult HLS L0 builds: summary

**All area and timing numbers below are Catapult HLS estimates from its own component library (rtl.rpt after `go extract`). They are not RTL synthesis results.** No downstream synthesis (Vivado, DC, RTL Compiler, Oasys) was run, and the Ultra datapath estimation (`ADVANCED_DPOPT`) was off. No comparison with the hand RTL is made here.

- Catapult version: 2026.3_1/1329181
- Generated by `hls/l0/report/hls_l0_report.py` from `hls/l0/out/*/rtl.rpt`, `sim/hls_l0_*/summary.txt` and the C test log.
- Flow and settings: `hls/l0/tcl/hls_l0.tcl` (OPT_CONST_MULTS full, RESET_CLEARS_ALL_REGS no, clock overhead default 20%).
- `fpga`: mgc_Xilinx-ZYNQ-1_beh (xc7z020clg400-1)
- `asic`: nangate-45nm_beh (Nangate 45 nm open cell library)
- cfg: c0 = combinational CCORE (latency 0), p1 / p2 = sequential CCORE, II = 1, output write fixed at c-step 1 / 2.
- FPGA area: LUTs, DSP and MUX_CARRYs as estimated by the Zynq-7000 (-1) library; flip-flops are not in the FPGA area score, see reg bits. ASIC area: Catapult area score of nangate-45nm_beh (the report prints no unit; not converted).
- reg bits: total register bits of the generated module (Register-to-Variable Mappings). The adapter valid flops (LATENCY bits) are not included.
- Simulation: unchanged tb_mod_red / tb_mod_mul via `sim/run.sh hls_l0_<block>_<lib>`; data = output data checks (exhaustive), valid = valid_o alignment checks.
