# N2 결과: C 전체 구현과 외부 기준 교차 검증 (G1)

작성 2026-11-26 (hw-worker). 모든 수치는 이 서버(core 1개, gcc 8.5 `-O2`)에서 실제로 실행한 결과다. **[측정]** = 시뮬레이션 실행 결과, **[문헌]** = 외부 출처의 수치, **[그림]** = 문헌 그림에서 눈으로 읽은 값(정밀도 약 ±0.1 decade), **[추정]** = 가정이 들어간 값.

- 원자료: `model/results/*.txt`(fer 출력), `model/results/aff/*.txt`(AFF3CT 출력), 설정 `model/cfg/*.cfg`, `model/cfg/aff/*.args`. 표는 `S_IN=<파일> python3 -I tools/summ.py`로 만든다(95% 구간은 Wilson).
- FER은 codeword 전체 비교의 frame 오류율. AWGN은 BPSK, `Eb/N0`의 rate는 k/n(802.3an 1723/2048, C2 7156/8176, 자체 code 8192/9216). 802.3an은 AFF3CT와 같게 all-zero codeword(AZCW), C2와 자체 code는 random codeword.
- decoder 이름: `SPA-F/L` = float sum-product flooding/layered, `NMS-F/L a` = float normalized min-sum(계수 a), `fix(wc,wm,wa)` = 고정소수점 layered NMS 12/16(numeric.md), 상한 iteration은 각 표에.

- 독립 seed의 SPA-F는 참조와 맞는다(6.56e-5 대 6.90e-5/7.29e-5). R1의 4.0 dB 편차는 세 decoder가 같은 frame을 쓴 데서 온 상관된 요동으로 보인다.
- 전체 판단: 802.3an, C2, m128에서 이 구현과 참조 구현(AFF3CT 2018 곡선, 직접 빌드한 v4.7.4) 사이 비교 약 25개 중 |z| > 2는 "AFF3CT 두 결과를 합친 값" 대비의 NMS-F 4.0 dB(−2.2)와 SPA-L 4.0 dB(−2.0) 둘이고, 같은 비교를 현재 빌드(v4.7.4) 하나와 하면 −1.1, −1.7이다. 두 AFF3CT 결과끼리도 NMS-F 4.0 dB에서 1.0σ 다르다. 비교 수를 고려하면 통계 오차 안으로 판단한다. 다만 4.0 dB(FER 1e-4~1e-5)의 차이가 모두 이 구현이 약간 좋은 방향이라는 점은 남겨 둔다. 후보 원인(**미확인**): AFF3CT float32의 메시지 범위(SPA의 `2 atanh(1 - eps)` 상한 약 16.6 대 double 약 36.7)와 FE 정의 차(AFF3CT는 정보 비트 기준, 이 구현은 codeword 전체: 이 차이는 AFF3CT 쪽 FER을 낮추는 방향이라 설명이 되지 않음).

## 9. spec 변경 제안 (바꾸지 않았다. 오케스트레이터 판단)
1. **scope.md 3.2 "메시지 Q, R 폭 w_m = w_ch"**: 6.2절의 불안정 때문에 (w_ch, w_m) = (6, 6)과 (5, 6, 7)(AWGN 입력 포화)은 FER 바닥 2e-3~1e-2와 대량 undetected를 보였다. N2b E1에 w_m = w_ch + 1 후보((6,7,8), (5,6,7)의 입력 scale 축소, (4,5,6))를 넣고, 불안정 판정(undetected 수, 잔여 오류 > 500 frame 수)을 지표로 추가하기를 권한다. N2의 기본 곡선은 (6,7,8)로 냈다.
2. **scope.md 3.2 "APP 폭 w_a = w_m + 1, w_m + 2"**: Q를 w_m으로 포화하는 이 알고리즘에서는 w_a = w_m + 1이면 APP 포화가 없다(6.2). w_m + 2는 BRAM 폭만 늘린다. (8 bit APP는 (6,7,8)에서 그대로 맞다.)
3. **channel.md 1.1 MLC 비트 순서**: 문장 "앞 비트 = upper(MSB) page ... 그러면 lower page 경계 1개(P1|P2), upper page 경계 2개"는 Gray 11/10/00/01과 맞지 않는다(앞 비트 1,1,0,0이 경계 1개). 코드는 "경계 1개 page = lower(앞 비트)"로 구현했다(`chan.c`). 문서 문장 정정 필요.
4. **channel.md 2.1 [R3] 효과 순서**: [R3] 2.4절과 Fig. 1에서 순서(이상 프로그램 → RTN → CCI → retention 감소)와 retention이 Vth를 낮추는 방향을 원문 확인. CCI의 이웃 수(다음 word line의 수직 1 + 대각 2)와 이웃 ΔVt(= 이웃 state의 프로그램 이동량 평균)는 여전히 [추정]이다. retention의 x는 이상 프로그램 Vth로 썼다(원문 "initial threshold voltage").
5. **scope.md 6.2 방향성 "LLR 전부 0(erasure, 상한까지 돌고 실패)"**: all-zero LLR이면 hard decision이 all-zero codeword라 ET-A가 1 iteration에 ok로 끝난다(`make test`). 테스트 의도를 "all-zero word가 codeword로 받아들여진다"로 바꾸기를 권한다.
6. **channel.md 3.2/[R5] 격자 값**: 미확인이던 A1~A3 전체를 원문에서 옮겨 `data/params/tlc_cui2021.txt`에 두었다(H5). 문헌 범위 안에서는 raw BER 변화가 작아(7절) read retry 실험은 α 이외의 knob(평균 이동 β, 또는 [R3] MLC 모델의 N, t)이 필요하다.

## 10. 확인하지 못한 것, 한계
- FER 1e-4 근처까지 오류 frame 50개 기준을 다 채우지 못한 점이 있다: 점당 시간 상한(AWGN 900초, NAND 500초, 802.3an 1,800초) 때문에 낮은 FER 점은 오류 0~22개(표에 frame 수와 함께 적음). 자체 code의 곡선이 매우 가팔라(AWGN 0.2 dB에 3자릿수) FER 1e-4~1e-5 구간에 점이 하나뿐인 곡선이 많다. 오류 50개 기준으로 FER 1e-4를 찍으려면 점당 약 5e5 frame(m128 fix 약 10~20분)이 더 필요하다.
- error floor: FER ≥ 약 1e-5 범위에서 징후 없음. 그 아래는 보지 못했다(C3 조건의 판단 근거로 충분하지 않음).
- MLC 모델의 FER 곡선, MSB/CSB page의 FER, LUT 불일치(공칭 조건) FER, read retry 정책의 FER/지연 곡선은 돌리지 않았다(기능은 구현, `make test`에서 동작 확인).
- GDBF(bit flipping)는 구현하지 않았다(이번 범위 지시에 없음, scope.md 2절 표에는 비교용으로 있음).
- AFF3CT와의 frame 단위(같은 잡음) 비교는 하지 않았다(USER 채널 입력 미사용). 비교는 FER 통계다. BCH의 AFF3CT 비교도 하지 않았다(shortened 지원 미확인). BCH는 이항 꼬리식과 MC 일치로 확인.
- AFF3CT 설정 저장소와 참조 곡선 저장소의 라이선스, CCSDS 문서의 복제 조건은 미확인(저장소에 넣지 않음).
- 그림 A-2 값은 눈으로 읽은 값이다.
