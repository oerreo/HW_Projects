# 프로세스 노출 최소화

공용 서버의 다른 사용자(와 그 사용자의 Claude 세션)는 `ps`로 이 계정의 프로세스 이름과 인자 전체를 볼 수 있다(`/proc`에 hidepid 없음).
목표: 다른 사용자에게는 "Questa, Catapult, NC, DC가 돌고 있다"는 것만 보이고, 무슨 프로젝트의 무슨 모듈인지는 보이지 않게 한다(2026-11-17 사용자 지시).

## 보이는 것과 보이지 않는 것
- 보임(막을 수 없음): 프로세스의 실행 파일 이름과 명령행 인자 전체, CPU와 메모리 사용량, 실행 시간, `/tmp` 최상위의 파일과 디렉토리 이름.
- 보이지 않음: 프로세스의 작업 디렉토리(cwd), 환경변수, 권한을 막은 디렉토리 안의 파일.
- root와 서버 관리자는 전부 볼 수 있다. 이 규칙으로 막을 수 없다.

## 규칙
1. **디렉토리 권한**: `/home/theo/work/research`는 700으로 유지한다. `umask 077`(`scripts/env.sh`가 설정). 새로 만드는 최상위 디렉토리를 그룹이나 타인에게 열지 않는다.
2. **임시 파일**: 툴의 임시 파일은 `/tmp` 최상위가 아니라 비공개 디렉토리(`scripts/env.sh`가 `TMPDIR`을 `/tmp/.rt-<uid>/t`로 설정)로 보낸다. 시뮬레이터의 표준 출력 파일과 DPI 자동 컴파일 산출물이 여기에 해당한다. `/tmp` 최상위에 프로젝트나 모듈 이름이 든 파일/디렉토리를 만들지 않는다.
3. **명령행 인자에 정체를 드러내는 문자열을 넣지 않는다**: 프로젝트 이름, 모듈과 TB 이름, 알고리즘 이름, 테스트 이름, 그것들이 들어간 경로.
   - 툴은 실행 디렉토리로 `cd`한 뒤 **인자 파일**로 실행한다: `vlog -f c.f`, `vsim -f r.f`, `irun -f r.f`, `catapult -shell -f run.tcl`, `dc_shell -f run.tcl`. top 이름, generic, plusarg, 로그 경로는 전부 인자 파일 안에 둔다. 인자 파일과 로그는 상대 경로의 일반적인 이름(`c.f`, `r.f`, `run.tcl`, `run.log`)을 쓴다.
   - 래퍼 스크립트에 테스트 이름을 인자로 넘기지 않는다. 환경변수로 넘긴다(환경변수는 타인에게 보이지 않는다). 예: `T=<test> ./sim/run.sh` 가 아니라 셸 변수로 export한 뒤 `./sim/run.sh`. 스크립트 이름 자체도 일반적이어야 한다(`run.sh`).
   - 자식 프로세스에 전달되는 인자도 마찬가지다. 스크립트 안에서 `bash other.sh <이름>`, `make TARGET=<이름>`, `python3 tool.py <경로>` 형태를 피하고 환경변수나 설정 파일로 넘긴다.
   - golden model 테스트 바이너리, 벡터 생성기처럼 수 초 이상 도는 자체 프로그램도 인자 대신 환경변수나 설정 파일을 쓴다. 실행 파일 이름은 일반적으로(`t`, `gen`) 두거나 `./run` 같은 래퍼로 실행한다.
4. **Bash 툴로 내는 명령**: 명령 문자열 전체가 `bash -c`의 인자로 `ps`에 보인다. 수 초 이상 걸리는 명령은 경로와 이름이 드러나지 않는 형태로 낸다.
   - 작업 디렉토리로 먼저 이동해 둔다(셸의 cwd는 호출 간 유지된다). 이후 긴 명령은 상대 경로의 짧은 형태로만 실행한다.
   - 긴 명령은 프로젝트 안의 작업 파일(예: `sim/.job`)에 적어 두고 `sh sim/.job` 처럼 실행한다. 또는 환경변수 파일을 source한 뒤 일반적인 스크립트를 실행한다.
   - agent(subagent)의 Bash 호출은 매번 cwd가 초기화되어 `cd <프로젝트 경로> && sh sim/.job` 형태가 되기 쉽다. 이 문자열이 실행 내내 보인다. 프로젝트 경로를 비공개 포인터 파일(`/tmp/.rt-<uid>/p`, 600)에 적어 두고 `cd "$(cat /tmp/.rt-$(id -u)/p)" && sh sim/.job`으로 실행한다(2026-11-19 S4-3에서 확인).
   - job 파일의 수정과 실행은 반드시 별도 Bash 호출로 한다(수정 명령에 테스트 이름이 들어가기 때문).
   - `grep`, `sed`, `ls` 같은 1초 미만의 명령은 그대로 써도 된다(노출 시간이 매우 짧다). 다만 긴 명령과 한 줄로 묶지 않는다(묶으면 긴 명령이 도는 동안 전체 문자열이 보인다).
5. **확인 방법**: 새 실행 방식을 만들면 실행 중에 `tr '\0' ' ' < /proc/<pid>/cmdline`으로 자기 프로세스와 자식 프로세스의 인자를 직접 보고, 프로젝트/모듈/테스트 이름이 없는지 확인한다.
6. agent에게 일을 맡길 때 이 파일을 읽게 한다.
