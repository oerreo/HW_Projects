# 머신·툴 사용 제한

공용 서버다. 아래는 예외 없이 지킨다.

- **병렬도 최대 2**: 이 연구 워크스페이스(`/home/theo/work/research`)에서 띄운 무거운 프로세스(시뮬레이션, Catapult, 컴파일, 벡터 생성)를 동시에 2개까지. 다른 세션(회사 작업)의 프로세스는 세지 않는다(2026-11-17 사용자 확인). agent 2개가 각각 하나씩 돌리면 한도이므로, 오케스트레이터의 검수 재실행은 agent의 무거운 작업과 겹치지 않게 순서를 잡는다.
- **CPU core를 많이 쓰지 않는다**: 프로세스 하나는 core 하나만 쓰게 한다. `make -j`는 `-j2` 이하. 툴의 멀티스레드/멀티코어 옵션(시뮬레이터의 병렬 모드, 합성 툴의 `set_host_options -max_cores` 등)은 켜지 않거나 1로 둔다. 병렬 회귀(xargs -P, GNU parallel, 백그라운드 `&` 다중 실행)는 쓰지 않고 순차로 돌린다.
- **라이선스는 eval만, 서버는 bm06만** (2026-11-19 사용자 지시): 툴은 eval 환경(`scripts/env.sh questa|hls|rise`)으로만 실행하고 라이선스 서버는 bm06만 쓴다. `env.sh`가 다른 서버가 설정되면 실행을 거부한다. NC(irun)와 DC는 eval/bm06이 아니므로 쓰지 않는다. 필요하면 사용자에게 그 사실을 알리고 그 실행 한 번에 대한 허락을 받는다. 다른 머신(bm03 등)에서 실행하지 않는다.
- **Vivado 합성/구현 금지**: 이 머신에서 `vivado`를 실행하지 않는다. FPGA 작업은 Tcl/XDC/소스를 준비하고 사용자가 자기 환경에서 돌린다. 결과 리포트는 사용자가 전달해주면 분석한다.
- **DC는 허락받은 시점에만**: `dc_shell` 실행 전 반드시 사용자에게 무엇을(대상 모듈, 예상 시간) 돌릴지 알리고 승인을 받는다. 이전 승인은 다음 실행에 이어지지 않는다. 스크립트 작성은 자유.
- Catapult 내부에서 downstream 합성(DC/Vivado 호출)을 켜지 않는다. Catapult 자체 리포트까지만 사용한다.
- 긴 작업(수 분 이상)은 background로 돌리고, 끝나면 로그를 확인한다. 걸려 있는 프로세스는 남기지 않는다.
- 시뮬레이션 산출물(work 라이브러리, wave, 로그)은 `sim/` 아래에 두고 커밋 대상에서 제외한다. 대용량 wave dump는 디버그할 때만 켠다.
